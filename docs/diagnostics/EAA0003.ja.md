# EAA0003: 禁止された型を公開しない

[English](EAA0003.md) | 日本語

| 項目 | 内容 |
| --- | --- |
| カテゴリ | EntityAccessAnalyzer |
| 標準重大度 | Error |
| 既定で有効 | はい |
| Code Fix | なし |

## メッセージ

> Entity '{0}' はメンバー '{1}' を通じて禁止された型 '{2}' を公開しています

`{0}`は対象Entity、`{1}`は公開するメンバー、`{2}`は問題の型です。
入れ子の型が原因の場合は、その内側の型が問題になります。

## 原因

Entityの読み取りAPIなどから、次の型を公開しています。

- `ICollection` / `ICollection<T>`、またはそれらを実装・継承する型で、許可リストにないもの。
  例：配列、`List<T>`、`Dictionary<TKey, TValue>`、`IList<T>`。
- `Memory<T>`、`Span<T>`、`ArraySegment<T>`。
- `Action`、`Func`、独自デリゲート型。

コレクションの禁止判定は`IEnumerable`の実装だけでは行いません。
`IEnumerable`などを宣言型として直接公開する規則は[EAA0004](EAA0004.ja.md)です。

## 違反例

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public List<string> Items => _items; // EAA0003
}
```

getterしかなくても、呼び出し側で`order.Items.Clear()`などの変更操作ができます。

## 修正例

読み取り専用の型で公開します。

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IReadOnlyList<string> Items => _items;
}
```

この規則は宣言型を検査します。実体へのダウンキャストまで防ぐものではありません。

## 許可される標準型

| 分類 | 型 |
| --- | --- |
| 読み取り専用インターフェイス | `IReadOnlyCollection<T>`、`IReadOnlyList<T>`、`IReadOnlyDictionary<TKey, TValue>`、`IReadOnlySet<T>` |
| 不変コレクション | `ImmutableArray<T>`、`ImmutableList<T>`、`ImmutableHashSet<T>`、`ImmutableSortedSet<T>`、`ImmutableDictionary<TKey, TValue>`、`ImmutableSortedDictionary<TKey, TValue>`、`ImmutableQueue<T>`、`ImmutableStack<T>` |
| 不変コレクションのインターフェイス | `IImmutableList<T>`、`IImmutableSet<T>`、`IImmutableDictionary<TKey, TValue>`、`IImmutableQueue<T>`、`IImmutableStack<T>` |
| Frozenコレクション | `FrozenSet<T>`、`FrozenDictionary<TKey, TValue>` |
| 標準の読み取り専用ラッパー | `ReadOnlyCollection<T>`、`ReadOnlyDictionary<TKey, TValue>`、`ReadOnlyObservableCollection<T>`、`ReadOnlySet<T>` |
| 読み取り専用メモリー | `ReadOnlyMemory<T>`、`ReadOnlySpan<T>` |
| 文字列 | `string` |

不変コレクションの変更可能な`Builder`型は例外に含めません。
標準型と同名の独自型や、許可インターフェイスを実装しているだけの変更可能な型を、名前や実装関係だけで許可しません。

不変コレクションとそのインターフェイスは`System.Collections.Immutable`、
Frozenコレクションは`System.Collections.Frozen`の標準型を指します。
標準.NETに非ジェネリックの`IReadOnlyCollection` / `IReadOnlyList`はありません。

独自の具象型・インターフェイスでも、`ICollection`系を持たなければ、コレクションという理由だけでは禁止しません。
これは`IReadOnlyList<T>`などを継承した独自インターフェイスにも適用します。

## 検査する場所と入れ子

public getter、フィールド、インデクサー、変換先、`Deconstruct`の`out`引数に適用します。
`ref readonly`でも参照先の型を検査します。

次の中身も再帰的に検査します。

- 標準の許可コレクションの要素型と、辞書のキー型・値型。
- `ReadOnlyMemory<T>` / `ReadOnlySpan<T>`の要素型。
- `ValueTuple`の要素型。タプル構文も同じ扱いです。

例えば`IReadOnlyList<List<string>>`の内側の`List<string>`は違反です。
内側も`IReadOnlyList<string>`などで公開する必要があります。

型引数`T`は、制約から禁止対象と分かる場合だけ診断します。
複数の制約のいずれかから`ICollection` / `ICollection<T>`系を持つと分かれば禁止します。
読み取り専用の制約が併存しても、この判定を打ち消しません。
ただし、許可された標準型を直接指定した制約は、その型が`ICollection`系を実装していても例外です。
例えば`where T : ReadOnlyCollection<int>`は許可し、これに`ICollection<int>`制約も別途指定した場合は禁止します。

許可コレクションを指定した制約の要素型・キー型・値型にも、同じ再帰検査を適用します。
例えば`where T : IReadOnlyList<List<int>>`の`T`を公開すると、内側の`List<int>`を診断します。
`where T : U`のように別の型パラメーターを経由する制約も検査します。

## 検査しない範囲

- 通常の入力引数や、コンストラクターの`out`引数の型。
- getterが非公開で、public `init`だけを持つプロパティの型。
- `Task<T>`、`ValueTask<T>`、`Nullable<T>`などのラッパーの中身。
- 独自コレクションの列挙要素型。独自型自身が`ICollection`系なら、その型に対する禁止判定は行います。
- 任意の参照先オブジェクトのメンバー。
- ポインター型・関数ポインター型。

publicイベントは許可します。デリゲート型のプロパティ・フィールドの公開とは区別します。

許可されたAPIすべての戻り値・`out`引数へ、公開型検査を一律に広げることはしません。
例えば`public Entity(out List<int> items)`や、
`public List<int> Items { private get; init; }`は、その型を理由には禁止しません。
対象外の`Address`やR3の`ReadOnlyReactiveProperty`なども、内部のメンバーまで走査しません。
ただし、その公開型自身が禁止規則に該当する場合は、その規則を適用します。

継承時の隠蔽、診断位置、複数違反の報告については[EAA0001の共通報告方針](EAA0001.ja.md#継承と診断位置)を参照してください。
