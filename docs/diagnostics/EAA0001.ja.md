## メッセージ

> Entity '{0}' はメンバー '{1}' を通じてpublicな書き込み操作を公開しています

`{0}`は対象Entity、`{1}`は書き込みを公開しているメンバーです。

## 原因

Entityの公開APIに、次のいずれかがあります。

- プロパティまたはインデクサーのpublic `set`。
- 再代入可能なpublicフィールド。
- 書き込み可能な`ref`戻り値。
- 参照の再代入、または参照先への書き込みが可能なpublic refフィールド。

外部アセンブリからEntityの状態を直接変更できるAPIを制限します。
対象型や継承の扱いは[共通ルール](../entity-api-policy.md#対象となるコード)を参照してください。

## 違反例

```csharp
namespace App.Entities;

public class Player
{
    private int _score;

    public string Name { get; set; } = ""; // EAA0001: public setter
    public int Level;                     // EAA0001: 書き込み可能フィールド
    public ref int Score => ref _score;   // EAA0001: 書き込み可能な参照
}
```

## 修正例

書き込みを非公開にし、読み取りだけを公開します。

```csharp
namespace App.Entities;

public class Player
{
    private int _score;

    public string Name { get; internal set; } = "";
    public readonly int Level;
    public ref readonly int Score => ref _score;

    public Player(int level, int score)
    {
        Level = level;
        _score = score;
    }
}
```

`internal`を使うと同一アセンブリから変更できます。Entity内部だけで変更するなら`private`を使用します。
初期化時の指定だけを許可する場合は、public `init`も使用できます。

## 許可される操作と注意点

- publicコンストラクターとpublic `init`は許可します。
- public `const` / `readonly`フィールド、`ref readonly`戻り値は許可します。
- publicイベントの購読・解除は許可します。
- 明示的インターフェイス実装は許可します。
- `readonly ref`フィールドは参照先へ書き込めるため禁止します。
- `ref readonly`フィールドは参照自体を再代入できるため禁止します。
- `readonly ref readonly`フィールドは両方を制限するため許可します。

public getterは許可し、公開型を[EAA0003](EAA0003.ja.md) / [EAA0004](EAA0004.ja.md)で検査します。
インデクサーも通常のプロパティと同じ扱いです。
イベントに独自の`add` / `remove`アクセサーがあっても、その内部処理は検査しません。

`readonly`でも参照先のオブジェクトは変更できる場合があります。
例えば`public readonly List<int> Values`は、この診断ではなく[EAA0003](EAA0003.ja.md)の対象です。

継承したpublic setterの可視性は、派生型から単純に狭められません。
その場合は基底型の公開APIや継承関係を見直します。
