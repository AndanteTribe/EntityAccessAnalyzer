# EAA0003: Do not expose prohibited types

English | [日本語](EAA0003.ja.md)

| Property | Value |
| --- | --- |
| Category | EntityAccessAnalyzer |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Entity '{0}' exposes prohibited type '{2}' through member '{1}'

`{0}` is the entity, `{1}` is the exposing member, and `{2}` is the prohibited type.
For a nested type violation, the offending inner type is identified.

## Cause

An entity exposes one of the following types through a read API or another checked output:

- `ICollection` / `ICollection<T>`, or a type implementing or inheriting either interface,
  unless the type is explicitly allowed. Examples include arrays, `List<T>`, `Dictionary<TKey, TValue>`, and `IList<T>`.
- `Memory<T>`, `Span<T>`, or `ArraySegment<T>`.
- `Action`, `Func`, or a custom delegate type.

Implementing `IEnumerable` alone does not make a collection type prohibited.
Direct exposure as `IEnumerable` or a related enumeration-only interface is covered by [EAA0004](EAA0004.md).

## Violation

The examples assume `[assembly: EntityAccessScope("App.Entities", "App.Entities.*")]`
is configured in another file. Each example is independent.

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public List<string> Items => _items; // EAA0003
}
```

Even without a setter, consumers can call modifying operations such as `order.Items.Clear()`.
## Fix

Expose the collection through a read-only type.

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IReadOnlyList<string> Items => _items;
}
```

This rule checks the declared type. It does not prevent downcasting to the underlying implementation.

## Allowed standard types

| Family | Types |
| --- | --- |
| Read-only interfaces | `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `IReadOnlyDictionary<TKey, TValue>`, `IReadOnlySet<T>` |
| Immutable collections | `ImmutableArray<T>`, `ImmutableList<T>`, `ImmutableHashSet<T>`, `ImmutableSortedSet<T>`, `ImmutableDictionary<TKey, TValue>`, `ImmutableSortedDictionary<TKey, TValue>`, `ImmutableQueue<T>`, `ImmutableStack<T>` |
| Immutable collection interfaces | `IImmutableList<T>`, `IImmutableSet<T>`, `IImmutableDictionary<TKey, TValue>`, `IImmutableQueue<T>`, `IImmutableStack<T>` |
| Frozen collections | `FrozenSet<T>`, `FrozenDictionary<TKey, TValue>` |
| Standard read-only wrappers | `ReadOnlyCollection<T>`, `ReadOnlyDictionary<TKey, TValue>`, `ReadOnlyObservableCollection<T>`, `ReadOnlySet<T>` |
| Read-only memory | `ReadOnlyMemory<T>`, `ReadOnlySpan<T>` |
| Strings | `string` |

Mutable `Builder` types are not included in the immutable collection exceptions.
A custom type sharing a standard type's name, or a mutable type merely implementing an allowed interface,
is not automatically allowed.

Immutable collection names refer to standard types in `System.Collections.Immutable`;
frozen collection names refer to `System.Collections.Frozen`.
.NET has no standard non-generic `IReadOnlyCollection` / `IReadOnlyList` interfaces.

A custom concrete type or interface without an `ICollection` contract is not prohibited merely
because it is a collection. This also applies to custom interfaces inheriting `IReadOnlyList<T>`.

## Checked locations and nested types

The rule applies to public getters, fields, indexers, conversion targets, and `Deconstruct` out parameters.
The referent type of a `ref readonly` API is also checked.

The following are inspected recursively:

- Elements of allowed standard collections, and dictionary keys and values.
- Elements of `ReadOnlyMemory<T>` / `ReadOnlySpan<T>`.
- Elements of `ValueTuple`, including tuple syntax.

For example, the inner `List<string>` in `IReadOnlyList<List<string>>` is prohibited.
Expose the inner collection through a type such as `IReadOnlyList<string>` as well.

A type parameter `T` is reported only when its constraints establish that it is prohibited.
If any constraint establishes an `ICollection` / `ICollection<T>` contract, the type is prohibited;
an additional read-only constraint does not override that result.
However, a constraint directly naming an allowed standard type is exempt even if that type implements `ICollection`.
For example, `where T : ReadOnlyCollection<int>` is allowed, but separately adding an `ICollection<int>` constraint is prohibited.

Elements, keys, and values of allowed collection constraints are inspected recursively as well.
For example, exposing `T` with `where T : IReadOnlyList<List<int>>` reports the inner `List<int>`.
Constraints through another type parameter, such as `where T : U`, are also followed.

## Out of scope

- Types of ordinary input parameters and constructor `out` parameters.
- Types of properties with a non-public getter and a public `init` accessor.
- Contents of wrappers such as `Task<T>`, `ValueTask<T>`, and `Nullable<T>`.
- Enumeration element types of custom collections. A custom collection itself is still checked for `ICollection` contracts.
- Members of arbitrary referenced objects.
- Pointer and function pointer types.

Public events are allowed and are treated differently from delegate-valued properties and fields.

Type inspection is not extended uniformly to every return value or out parameter of every allowed API.
For example, `public Entity(out List<int> items)` and
`public List<int> Items { private get; init; }` are not prohibited because of that type.
Members inside an out-of-scope `Address` type or R3's `ReadOnlyReactiveProperty` are not traversed.
However, a rule still applies when the exposed type itself meets that rule's conditions.

For inherited member hiding, diagnostic locations, and multiple violations, see the [shared reporting rules under EAA0001](EAA0001.md#inheritance-and-diagnostic-locations).

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.EAA0003.severity = error
```

Use `warning` to report a warning or `none` to disable this rule. For a local suppression,
use `#pragma warning disable EAA0003` and `#pragma warning restore EAA0003`.
