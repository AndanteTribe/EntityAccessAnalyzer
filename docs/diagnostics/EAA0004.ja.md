# EAA0004: 列挙専用の型で公開しない

[English](EAA0004.md) | 日本語

| 項目 | 内容 |

| 標準重大度 | Error |

## メッセージ

> Entity '{0}' はメンバー '{1}' を通じて列挙専用の型 '{2}' を公開しています。許可されたコレクションAPIを使用してください

`{0}`は対象Entity、`{1}`は公開するメンバー、`{2}`は列挙専用の型です。

## 原因

Entityの公開APIに、次の型を使用しています。

- `System.Collections.IEnumerable`
- `System.Collections.Generic.IEnumerable<T>`
- `System.Collections.Generic.IAsyncEnumerable<T>`

型引数の制約から列挙しか保証されない場合も対象です。

この規則の目的は、書き込み操作の制限ではなく、列挙だけを契約とするAPIの制限です。
遅延実行や繰り返し列挙に伴う処理の再実行を考慮し、Entityのコレクションは
`IReadOnlyCollection<T>`や`IReadOnlyList<T>`などで公開します。
実際に二重列挙しているかを呼び出し側で解析する規則ではありません。

## 違反例

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IEnumerable<string> Items => _items; // EAA0004
}
```

## 修正例

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IReadOnlyCollection<string> Items => _items;
}
```

呼び出し側は、件数を得るために列挙せず`Count`を使用できます。
添字によるアクセスも必要なら`IReadOnlyList<T>`を使用します。
読み取り専用インターフェイスでも、繰り返し列挙のコストや副作用までは保証しません。

非同期ストリームの場合は、型名だけを置き換えることはできません。
Entity外のサービスでストリームを提供するか、取得済みの結果をEntityの読み取り専用コレクションとして公開します。

## 型引数の制約

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Catalog<T> where T : IEnumerable<string>
{
    public Catalog(T items) => Items = items;

    public T Items { get; } // EAA0004: 列挙しか保証されない
}
```

読み取り専用コレクションとして扱う契約なら、制約も`IReadOnlyCollection<string>`などへ変更します。
実際の型が不明な、無制約の`T`というだけでは診断しません。
複数の制約に`IReadOnlyCollection<T>`などの許可コレクション型が含まれる場合も、
列挙しか保証されないという理由では診断しません。

## 対象外と関連する規則

- 独自型が`IEnumerable<T>`を実装しているという理由だけでは、この診断を出しません。
- 独自型のまま公開する場合、その列挙要素型までは検査しません。
- `string`も対象外です。
- 標準の許可コレクションや`ValueTuple`などの中に列挙専用の型がある場合は、再帰検査の対象です。
- 変更可能なコレクションやデリゲートなどの公開は[EAA0003](EAA0003.ja.md)です。

公開型検査を適用する場所や、検査しないラッパーの範囲は[EAA0003](EAA0003.ja.md#検査する場所と入れ子)と共通です。
