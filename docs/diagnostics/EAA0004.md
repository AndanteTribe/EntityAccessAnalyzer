# EAA0004: Do not expose enumeration-only types

English | [日本語](EAA0004.ja.md)

| Property | Value |
| --- | --- |
| Category | EntityAccessAnalyzer |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Entity '{0}' exposes enumeration-only type '{2}' through member '{1}'; use an allowed collection API

`{0}` is the entity, `{1}` is the exposing member, and `{2}` is the enumeration-only type.

## Cause

An entity uses one of the following types in its public API:

- `System.Collections.IEnumerable`
- `System.Collections.Generic.IEnumerable<T>`
- `System.Collections.Generic.IAsyncEnumerable<T>`

Type parameters whose constraints guarantee only enumeration are also subject to this rule.

This rule restricts enumeration-only contracts, rather than write access.
To account for deferred execution and work repeated during re-enumeration, expose entity collections
through types such as `IReadOnlyCollection<T>` or `IReadOnlyList<T>`.
This rule does not analyze callers to detect actual multiple enumeration.

## Violation

The examples assume `[assembly: EntityAccessScope("App.Entities", "App.Entities.*")]`
is configured in another file. Each example is independent.

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IEnumerable<string> Items => _items; // EAA0004
}
```

## Fix

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Order
{
    private readonly List<string> _items = new();

    public IReadOnlyCollection<string> Items => _items;
}
```

Consumers can obtain the count from `Count` without enumerating the sequence.
Use `IReadOnlyList<T>` when indexed access is also needed.
A read-only interface does not guarantee the cost or absence of side effects of repeated enumeration.

An asynchronous stream cannot be fixed by merely changing the declared type.
Expose the stream through a service outside the entity scope, or expose already retrieved results
as a read-only collection on the entity.

## Type parameter constraints

```csharp
using System.Collections.Generic;

namespace App.Entities;

public class Catalog<T> where T : IEnumerable<string>
{
    public Catalog(T items) => Items = items;

    public T Items { get; } // EAA0004: only enumeration is guaranteed
}
```

If the API requires a read-only collection, change the constraint to a type such as `IReadOnlyCollection<string>`.
An unconstrained `T` is not reported merely because its actual type is unknown.
If multiple constraints include an allowed collection type such as `IReadOnlyCollection<T>`,
the API is not reported on the grounds that only enumeration is guaranteed.
Constraints guaranteeing a mutable collection, such as `ICollection<T>`, are covered by EAA0003;
inheriting `IEnumerable<T>` through that constraint does not additionally produce EAA0004.

## Exclusions and related rules

- A custom type is not reported merely because it implements `IEnumerable<T>`.
- When exposed as that custom type, its enumeration element type is not traversed.
- `string` is excluded.
- Enumeration-only types nested in allowed standard collections, `ValueTuple`, or other recursively checked types are inspected.
- Exposing mutable collections, delegates, and other prohibited types is covered by [EAA0003](EAA0003.md).

The checked API locations and excluded wrappers are shared with [EAA0003](EAA0003.md#checked-locations-and-nested-types).

For inherited member hiding, diagnostic locations, and multiple violations, see the [shared reporting rules under EAA0001](EAA0001.md#inheritance-and-diagnostic-locations).

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.EAA0004.severity = error
```

This rule has a separate ID, so its severity can be configured independently of write-access restrictions.
Use `warning` to report a warning or `none` to disable it. For a local suppression,
use `#pragma warning disable EAA0004` and `#pragma warning restore EAA0004`.
